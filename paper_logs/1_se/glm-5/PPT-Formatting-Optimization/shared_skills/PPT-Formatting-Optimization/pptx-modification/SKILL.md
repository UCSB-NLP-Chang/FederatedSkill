# PowerPoint (PPTX) Modification

## Overview
PPTX files are ZIP archives containing XML files. Modify them by extracting, editing XML, and repackaging.

## Quick Start

1. Extract the PPTX:
```python
import zipfile
zipfile.ZipFile('input.pptx', 'r').extractall('extracted/')
```

2. Key paths inside the archive:
- `ppt/presentation.xml` - slide order and references
- `ppt/_rels/presentation.xml.rels` - maps rId to slide files
- `ppt/slides/slideN.xml` - individual slide content
- `ppt/slideLayouts/`, `ppt/slideMasters/` - templates

3. Repackage after edits:
```python
with zipfile.ZipFile('output.pptx', 'w') as zf:
    for root, dirs, files in os.walk('extracted/'):
        for f in files:
            path = os.path.join(root, f)
            arcname = os.path.relpath(path, 'extracted/')
            zf.write(path, arcname)
```

## Critical: Slide Order Mapping

**Slide filenames (slide1.xml, slide2.xml) do NOT determine presentation order.** Always map rIds to files:

```python
def get_slide_order(extract_dir):
    """Get slides in correct presentation order."""
    # Parse presentation.xml for slide IDs and rIds
    pres_tree = ET.parse(os.path.join(extract_dir, 'ppt', 'presentation.xml'))
    pres_root = pres_tree.getroot()
    
    sldIdLst = pres_root.find('.//p:sldIdLst', NS)
    slide_order = []
    for sldId in sldIdLst.findall('p:sldId', NS):
        slide_order.append({'id': sldId.get('id'), 'rId': sldId.get('{http://schemas.openxmlformats.org/officeDocument/2006/relationships}id')})
    
    # Parse relationships to map rId -> file
    rels_tree = ET.parse(os.path.join(extract_dir, 'ppt', '_rels', 'presentation.xml.rels'))
    rels_root = rels_tree.getroot()
    rId_to_file = {}
    for rel in rels_root.findall('.//{http://schemas.openxmlformats.org/package/2006/relationships}Relationship'):
        rId_to_file[rel.get('Id')] = rel.get('Target')
    
    # Return slides in correct order
    return [(s['rId'], rId_to_file.get(s['rId'])) for s in slide_order]
```

## XML Namespace Handling

**Critical**: Python's ElementTree requires careful namespace handling.

```python
# Define namespaces (do NOT register 'xml' prefix - it's reserved)
NS = {
    'a': 'http://schemas.openxmlformats.org/drawingml/2006/main',
    'p': 'http://schemas.openxmlformats.org/presentationml/2006/main',
    'r': 'http://schemas.openxmlformats.org/officeDocument/2006/relationships',
}

# Register for output - filter ALL reserved/auto-generated prefixes
RESERVED_PREFIXES = {'xml'}  # 'xml' is reserved by XML spec
AUTO_PREFIXES = {'ns'}  # 'ns0', 'ns1', 'ns2' etc. are auto-generated

for prefix, uri in NS.items():
    if prefix not in RESERVED_PREFIXES and not prefix.startswith(tuple(AUTO_PREFIXES)):
        ET.register_namespace(prefix, uri)
```

**Warning**: Some PPTX files contain auto-generated namespace prefixes like `ns2`, `ns3` in their source XML. Do not attempt to register these - they are generated by ElementTree during parsing.

## Critical: Namespace Context for New Elements

**When creating NEW XML elements, use the correct namespace based on context:**

| Context | Namespace Prefix | Example Elements |
|---------|-----------------|------------------|
| Slide structure | `p:` | `p:sp`, `p:spTree`, `p:cSld` |
| Text content (inside txBody) | `a:` | `a:p`, `a:r`, `a:t`, `a:rPr` |
| Relationships | `r:` | `r:id` attributes |

**Common mistake**: Using `p:p` for paragraphs inside `txBody` instead of `a:p`. This produces invalid XML that may appear to work but renders incorrectly or causes errors.

```python
# WRONG - p: namespace for text content
p = ET.SubElement(txBody, '{http://schemas.openxmlformats.org/presentationml/2006/main}p')

# CORRECT - a: namespace for text content
a_ns = '{http://schemas.openxmlformats.org/drawingml/2006/main}'
p = ET.SubElement(txBody, f'{a_ns}p')
```

## Identifying Shape Types

### Text Boxes vs Placeholders vs Shapes

**Text boxes** have `txBox="1"` on `cNvSpPr`:
```python
def find_text_boxes(root, ns):
    for sp in root.findall('.//p:sp', ns):
        cNvSpPr = sp.find('.//p:cNvSpPr', ns)
        if cNvSpPr is not None and cNvSpPr.get('txBox') == '1':
            yield sp
```

**Placeholders** have `<p:ph>` in `<p:nvPr>`:
```python
def find_placeholders(root, ns):
    for sp in root.findall('.//p:sp', ns):
        ph = sp.find('.//p:nvPr/p:ph', ns)
        if ph is not None:
            yield sp, ph.get('type'), ph.get('idx')
```

**Regular shapes** have neither - they're auto shapes, pictures, or other elements.

Common placeholder types: `title`, `body`, `ctrTitle`, `subTitle`. Use type to identify purpose (e.g., `type="body"` for content area).

### Finding Shapes by Content Pattern

When you need to find shapes containing specific text:

```python
import re

def find_shapes_by_text(root, ns, pattern, is_regex=False):
    """Find shapes containing text matching a pattern.
    
    Args:
        root: XML root element
        ns: Namespace dict
        pattern: Text to match or regex pattern
        is_regex: If True, treat pattern as regex
    
    Returns:
        Generator of (shape, matched_text) tuples
    """
    for sp in root.findall('.//p:sp', ns):
        text = get_full_text(sp, ns)
        if text:
            if is_regex:
                if re.search(pattern, text):
                    yield sp, text
            elif pattern in text:
                yield sp, text

def find_shapes_by_exact_text(root, ns, exact_text):
    """Find shapes with exact text content (after stripping whitespace)."""
    for sp in root.findall('.//p:sp', ns):
        text = get_full_text(sp, ns).strip()
        if text == exact_text:
            yield sp, text
```

## Finding Text Content

### Multi-Run Text Extraction

**Important**: Text can be split across multiple `<a:r>` runs within a single paragraph. Always concatenate all `<a:t>` elements:

```python
def get_full_text(sp, ns):
    """Get complete text from a shape, handling multi-run text."""
    texts = []
    for t in sp.findall('.//a:t', ns):
        if t.text:
            texts.append(t.text)
    return ''.join(texts)
```

Example of split text in XML:
```xml
<a:p>
  <a:r><a:t>Segment B - </a:t></a:r>
  <a:r><a:t>Quarry Tide Stairs</a:t></a:r>
</a:p>
```

### Replacing Multi-Run Text

When replacing text that spans multiple runs, either:
1. Remove all runs and create a single new run, or
2. Keep first run's text and clear others:

```python
def replace_text_in_shape(sp, new_text, ns):
    """Replace all text in a shape with new text."""
    a_ns = '{http://schemas.openxmlformats.org/drawingml/2006/main}'
    runs = sp.findall('.//a:r', ns)
    if runs:
        # Keep first run, remove others
        first_run = runs[0]
        for run in runs[1:]:
            run.getparent().remove(run)
        # Set text in first run
        t = first_run.find('a:t', ns)
        if t is None:
            t = ET.SubElement(first_run, f'{a_ns}t')
        t.text = new_text
```

## Element Truth Value Testing

**Important**: ElementTree elements raise deprecation warnings when used in boolean context. Always use explicit checks:

```python
# WRONG - triggers DeprecationWarning
if element:
    ...
if not element:
    ...

# CORRECT
if element is not None:
    ...
if len(element) == 0:
    ...
# For findall results (lists)
if elements:  # This is OK for lists
    ...
```

Text properties are in `a:rPr` (run properties):

### Modifying Position
To reposition or resize a shape:
```python
def set_position(sp, ns, x=None, y=None, cx=None, cy=None):
    """Modify shape position and/or size. Values in EMUs."""
    a_ns = '{http://schemas.openxmlformats.org/drawingml/2006/main}'
    p_ns = '{http://schemas.openxmlformats.org/presentationml/2006/main}'
    
    xfrm = sp.find(f'.//{p_ns}spPr/{a_ns}xfrm', ns)
    if xfrm is None:
        return False
    
    off = xfrm.find(f'{a_ns}off', ns)
    ext = xfrm.find(f'{a_ns}ext', ns)
    
    if off is not None:
        if x is not None:
            off.set('x', str(x))
        if y is not None:
            off.set('y', str(y))
    
    if ext is not None:
        if cx is not None:
            ext.set('cx', str(cx))
        if cy is not None:
            ext.set('cy', str(cy))
    
    return True

# Example: center at bottom of slide (13.33" x 7.5" standard)
# 1 inch = 914400 EMUs
slide_width = 12192000   # 13.33 inches
slide_height = 6858000   # 7.5 inches
caption_width = 4572000  # 5 inches
caption_height = 548640  # ~0.6 inches

# Center horizontally: (slide_width - caption_width) / 2
x = (slide_width - caption_width) // 2
# Near bottom: slide_height - caption_height - margin
y = slide_height - caption_height - 100000

set_position(sp, ns, x=x, y=y, cx=caption_width)
```

## Adding New Slides

1. Create slide XML file (copy from existing slide as template)
2. Add relationship in `ppt/_rels/presentation.xml.rels`:
```xml
<Relationship Id="rId12" Type="http://schemas.openxmlformats.org/officeDocument/2006/relationships/slide" Target="slides/slide7.xml"/>
```
3. Add slide reference in `ppt/presentation.xml`:
```xml
<p:sldId id="260" r:id="rId12"/>
```
4. Create `ppt/slides/_rels/slide7.xml.rels` for slide relationships
5. Update `[Content_Types].xml` to include the new slide

### Creating Lists on New Slides

**Important**: Each list item must be in its own `<a:p>` paragraph element. Do NOT concatenate text into a single paragraph.

### Auto-Numbered Lists

For auto-numbered lists in content placeholders, use `<a:buAutoNum>`:
```python
def create_autonumbered_list(textBody, items, ns):
    """Create auto-numbered list in a content placeholder.
    
    Args:
        textBody: The txBody element to add paragraphs to
        items: List of text strings for each list item
        ns: Namespace dict
    """
    a_ns = '{http://schemas.openxmlformats.org/drawingml/2006/main}'
    
    for item in items:
        # Use a:p (drawingml), NOT p:p (presentationml)
        p = ET.SubElement(textBody, f'{a_ns}p')
        
        # Paragraph properties with auto-numbering
        pPr = ET.SubElement(p, f'{a_ns}pPr')
        pPr.set('lvl', '0')
        
        # Auto-number bullet
        buAutoNum = ET.SubElement(pPr, f'{a_ns}buAutoNum')
        buAutoNum.set('type', 'arabicPeriod')  # 1., 2., 3., etc.
        
        # Text run
        r = ET.SubElement(p, f'{a_ns}r')
        rPr = ET.SubElement(r, f'{a_ns}rPr')
        rPr.set('sz', '1400')  # 14pt
        rPr.set('dirty', '0')
        
        # Font and color
        solidFill = ET.SubElement(rPr, f'{a_ns}solidFill')
        srgbClr = ET.SubElement(solidFill, f'{a_ns}srgbClr')
        srgbClr.set('val', '6B7280')
        
        for tf in ['latin', 'ea', 'cs']:
            ET.SubElement(rPr, f'{a_ns}{tf}').set('typeface', 'Arial')
        
        t = ET.SubElement(r, f'{a_ns}t')
        t.text = item
```

## Common Batch Processing Patterns

### CSV-Driven Text Standardization

When standardizing text based on a CSV registry:

```python
import csv

def load_registry(csv_path):
    """Load CSV registry with observed->preferred mappings.
    
    Expects columns: observed_label, preferred_label, record_state
    Only uses rows where record_state is 'active' and preferred_label exists.
    """
    mapping = {}
    with open(csv_path, 'r') as f:
        reader = csv.DictReader(f)
        for row in reader:
            if row.get('record_state') == 'active' and row.get('preferred_label'):
                mapping[row['observed_label']] = row['preferred_label']
    return mapping

def standardize_text(text, mapping):
    """Apply standardization mapping to text."""
    return mapping.get(text, text)
```

### Tracking Unique Values for Summary Slides

When creating summary slides with unique processed values:

```python
def track_unique_in_order(values):
    """Track unique values maintaining order of first appearance."""
    seen = set()
    unique = []
    for v in values:
        if v not in seen:
            seen.add(v)
            unique.append(v)
    return unique
```

## Common Pitfalls

1. **Wrong slide mapping**: Slide file names (slide1.xml, slide2.xml) don't match presentation order. Check `presentation.xml.rels` to map rIds to files.

2. **Namespace registration errors**: Never register 'xml' prefix or auto-generated prefixes like 'ns0', 'ns1', 'ns2'. Filter them out.

3. **Wrong namespace for new elements**: Use `a:` prefix for text content elements (`a:p`, `a:r`, `a:t`) inside txBody, NOT `p:`. This is the most common cause of corrupted output.

4. **Element truth value warnings**: Use `is not None` for elements, not truthiness checks.

5. **Text not found**: Use `txBox="1"` attribute to identify text boxes vs title/content placeholders.

6. **Changes not saving**: Must write XML tree back to file with `tree.write()`.

7. **Corrupted output**: Include all files from original archive, not just modified ones.

8. **Missing Content_Types update**: When adding new slides, update `[Content_Types].xml`.

9. **Multi-run text missed**: Text split across multiple `<a:r>` elements must be concatenated. Single `<a:t>` extraction misses content.

10. **List items concatenated**: Each list item needs its own `<a:p>` paragraph. Concatenating text into one paragraph produces run-on output.

11. **Placeholder vs text box confusion**: Placeholders have `<p:ph>` in nvPr; text boxes have `txBox="1"`. Check both when locating elements.

12. **Output file location mismatch**: Verify the expected output path matches what tests or downstream processes expect. Check task requirements for specific output locations.

13. **Path handling in slide iteration**: When iterating slides from `get_slide_order()`, the returned paths are relative to `ppt/` (e.g., `slides/slide1.xml`). Join with the `ppt/` directory, not use directly.

### Debugging Test Failures

When manual verification passes but tests fail:

1. **Check output file location**: Verify the output path matches test expectations exactly. Tests may expect a specific filename or directory.

2. **Compare XML structure**: Extract both expected and actual output, compare key XML files:
   ```python
   import difflib
   def compare_xml(expected_path, actual_path):
       with open(expected_path) as f1, open(actual_path) as f2:
           diff = list(difflib.unified_diff(f1.readlines(), f2.readlines()))
           return diff
   ```

3. **Check relationship files**: Ensure `ppt/_rels/presentation.xml.rels` and slide `.rels` files are updated for new slides.

4. **Validate Content_Types.xml**: When adding slides, verify `[Content_Types].xml` includes the new slide override.

5. **Check slide order in presentation.xml**: The `<p:sldIdLst>` order determines presentation order, not file names.

6. **Verify text encoding**: Use `encoding='UTF-8'` and `xml_declaration=True` when writing XML.

7. **Check for orphaned elements**: Ensure removed elements don't leave behind empty parent containers.

8. **Verify test expectations early**: Before processing, check if tests specify expected output location, naming convention, or specific content requirements. Look for test files or configuration that define expectations.

9. **Validate against test criteria**: If tests check specific attributes (font size, color, position), verify each one explicitly rather than relying on visual inspection.
